## Context

What exists, read from the code rather than remembered:

- `SellPlanViewModel` (001) fetches every `Item`, keeps those that `qualifies` (desire ≤ 3 via `DesireLevel.isSellCandidate`, a value entered) plus anything already selected, and sorts with a private static `rank`: desire ascending, value descending (nil last), name, id. `SellPlanView`'s `private struct SellPlanRow` draws checkbox, name, category, the person's value in `monoValue`, and the `DesireDial`, inside an `HStack` with the default centre alignment, `.accessibilityElement(children: .combine)`. The screen's header reads "Lowest desire to keep first" and the wishlist detail's button subtitle "Browse your lowest desire-to-keep items"; both stay true under this plan, because desire stays the first key.
- `MarketSummary { medianCents: Int?, trend: MarketTrend? }` (002) is the one derivation every row surface reads, through `MarketSummary.summaries(forSubjects:in:now:)`: one `MarketIndex.load` of the figure rows, the median gated by `MarketFreshness`. `trend` is the figure record's stored `trendRawValue`, written by `MarketLocalStore.record` from the whole history, so it cannot disagree with the history it was computed over. It is **not** gated by freshness: the list rows draw an arrow on a stale figure. This plan leaves that surface alone (not in the spec) and gates the Sell Plan's own reading (§2).
- `MarketTrend.compute(history:)` picks `previous` as the most recent point at least seven days older than the latest and classifies at ±5 % with integer arithmetic (`20 * delta >= previous`). It returns only the classification; the percentage and the earlier reading's date the reason line needs are not surfaced anywhere.
- `MarketLocalStore.historyEntries(for:in:)` returns an item's points as `MarketHistoryEntry` values, oldest first. `MarketLocalStore.record(_:product:for:in:)` is the single writer of a figure row, its history point and its trend, and the only path a refresh takes; callers save.
- `TroveApp.isUITesting` reads `-uiTesting` once and routes `TroveStore.make` to the in-memory pair (`StorageMode.ephemeral`); the UI suite launches with exactly that argument and builds its own state through the UI. Nothing seeds anything today. The constitution's Testing section (amended 2026-09-06) already sanctions a seed on two conditions — gated on the built store's mode being in-memory, and on a second argument — and spec Decision 9 / criterion 12 already name `-seedSellPlan`. No constitution or spec edit is left for this plan to make.
- `MarketVocabularyTests` scans `MarketCopy.swift` and a named list of Market view files for the forbidden words after stripping allowed phrases ("asking prices" among them), and separately requires those view files to carry no string literal containing a space. `SourceScan.production` strips comments and drops everything from the first `#Preview`, so previews are outside every scan. `SellPlanView.swift` cannot join the list — its empty states legitimately say "worth" and "value" for the person's numbers. `SellPlanFramingTests` scans `SellPlanView.swift`'s literals and `SellPlanViewModel.swift`'s code (comments stripped) for gap-framing terms; new identifiers in either file must stay clear of them.
- `ThemeTypography` sizes every font with `fixedSize:` (or the fixed-size system fallback): the app has **no Dynamic Type**, a recorded 001 limitation (`specs/001-core-inventory/plan.md`, "Known v1 limitation: no Dynamic Type"). This bears on criterion 11 — see Q10.

## 1. Comparison and rise

```swift
nonisolated enum MarketTrend: String, Sendable, CaseIterable {
    struct Comparison: Sendable, Equatable {
        let latestCents: Int
        let previousCents: Int
        let previousAt: Date
        let trend: MarketTrend
        /// (latest − previous) × 100 / previous, the numerator exact, one division, half away from zero.
        var percent: Int
    }
    static func comparison(history: [MarketHistoryEntry]) -> Comparison?   // today's compute body, returning the struct
    static func compute(history: [MarketHistoryEntry]) -> MarketTrend?     // comparison(history:)?.trend
}

nonisolated struct MarketRise: Sendable, Equatable {
    let percent: Int
    let since: Date
    init?(comparison: MarketTrend.Comparison)   // nil unless comparison.trend == .up
}
```

Tests (`MarketTrendTests`, extended; the existing suite untouched and green — the by-construction proof, G10): `percent` for 1000→1050 = 5, 1000→1124 = 12, 1000→1125 = 13 (half away), **1000→1145 = 15** (the integer numerator gives 14500/1000 exactly; dividing first gives 0.145 × 100 = 14.499… → 14 — the one value that discriminates; 4000→4700 = 18 stays green under the divide-first mutation by IEEE luck, so it is a value pin, not the guard), 1000→950 = −5, 1000→850 = −15, 1000→1049 = 5 (rounds up, yet `.flat` — `MarketRise(comparison:)` is nil for it, so no sentence ever says "up 5 %" on a flat item); the **whole `Comparison`** pinned for points 20 d / 8 d / 1 d old with medians 500 / 1000 / 1040: `previousCents` 1000 and `previousAt` the 8-day date, from the same point (mutation: pick the oldest → red; take the date from one point and the median from another → red); `MarketRise(comparison:)` nil for `.flat` and `.down`, and `{ percent: 12, since: previousAt }` for `.up`.
